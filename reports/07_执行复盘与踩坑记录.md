# 执行复盘：踩过的坑、错因与防护

> 数据版本：v2（含复购路径，5% 用户产生第二单）。v1→v2 的关键数字变化见 [reports/00_项目总报告.md](00_项目总报告.md) 附录 D。

> **用途**：记录本项目从环境搭建到论文定稿全过程中**真实发生过**的错误。
> 每条都写清：现象 → 根因 → 怎么被发现 → 怎么解决 → 启示 → 现在由什么防住它。
> **维护规则**：任何新发现的问题必须追加到本文件，不允许只修代码不记账。
>
> 最后更新：v2（含复购路径）数字统一之后。

---

## 0. 一句话结论

本项目的错误几乎全部属于**静默失败**（silent failure）——不报错、不崩溃、结果看起来合理，但数字是错的。
这类错误才是数据分析最危险的部分。**能自动发现的错误，才算是被解决的错误**；靠人眼复查的，迟早复发。

按危害排序，本项目最该记住的三条：

1. **口径错误不会报错，只会让结论悄悄错掉**（共 3 次，全部由"两条独立路径交叉校验"抓到）。
2. **"我以为的"和"代码实际读的"经常不是一回事**（稳健性扫描 4 个扰动里 2 个完全没生效，结果与基准一模一样）。
3. **为了让排版更好看而加的宏，可能正在吃掉正文**（`\needspace` 导致丢失整节内容，且不报错）。

## 1. 环境与平台类

### 1.1 工作目录被 Windows 文件权限挡住

| 项 | 内容 |
|---|---|
| **现象** | 所有 shell 命令报 `SetNamedSecurityInfoW failed (Win32 5): grantWrite(...)`，无法创建任何文件 |
| **根因** | 工作目录缺少当前用户的 `WRITE_OWNER` 权限，沙箱无法下发写入授权 |
| **发现** | 第一条命令就失败，立即暴露（属于"会报错"的幸运情形） |
| **解决** | 用诊断脚本在目录上补一条"当前用户完全控制"项；备份与回滚命令留存至工作区外 |
| **启示** | 环境问题要**第一分钟**解决，不要带着"偶尔失败"继续干活——它会污染后续所有判断 |

### 1.2 pytest 临时目录权限异常

| 项 | 内容 |
|---|---|
| **现象** | 所有用 `tmp_path` 的测试报 `PermissionError: ...\Temp\pytest-of-<user>` |
| **根因** | 系统 Temp 下该目录 ACL 异常（与 1.1 同源） |
| **解决** | `pyproject.toml` 里把 `--basetemp` 重定向到项目内并加入 `.gitignore` |
| **启示** | 平台缺陷不必硬修，**绕开并记录**即可；但必须写进 AGENTS.md，否则队友会再踩一次 |

### 1.3 `.gitignore` 的 `data/` 误伤源码包

| 项 | 内容 |
|---|---|
| **现象** | `src/causal_growth/data/` 整个包（利润核算模块）无法入库，`git status` 里看不到 |
| **根因** | `.gitignore` 写的是 `data/`，git 会匹配**任意层级**名为 `data` 的目录 |
| **发现** | 准备提交时发现 `profit.py`、`tables.py` 不在清单里 |
| **解决** | 改为根锚定的 `/data/`、`/outputs/runs/` |
| **启示** | 忽略规则一律用 `/` 锚定根目录；**每次首提交都要逐项核对"关键源码是否真的进去了"** |

## 2. 数据口径类（本项目最危险的一类）

> 这三条都不会报错。它们的共同点是：数字看起来完全合理。

### 2.1 退款手续费被扣了两次

| 项 | 内容 |
|---|---|
| **现象** | "关系表聚合"路径算出的用户利润比"解析路径"最大差 **2.197 元** |
| **根因** | `revenue_net` 里减了一次手续费，`net_profit` 求和时又减了一次 |
| **发现** | **两条独立利润路径的交叉校验**——差值恰好等于手续费，一眼定位 |
| **解决** | `revenue_net` 回归"纯收入"语义，手续费单列一项，五项各减一次 |
| **启示** | 同一条口径写两遍不是冗余，而是**唯一有效的一致性检验**。只要两份实现能对比，口径 bug 无处藏身 |

### 2.2 `refunded` 对未下单用户也置 1

| 项 | 内容 |
|---|---|
| **现象** | 辅助表算出退款率 **74%**（业务上不可能） |
| **根因** | 退款标记按"随机数 < 退款率"生成，没有乘"是否已下单" |
| **发现** | 人眼看到 74% 觉得荒谬——**这次是靠常识抓的，不是靠测试** |
| **解决** | `refunded = (u < rate) & (y_obs == 1)` |
| **启示** | 分母缩小而分子没缩小时，比率会被放大到荒谬值。**所有比率都要问一句"分母是什么"** |

### 2.3 券核销率 54.6% 对上转化率 15%

| 项 | 内容 |
|---|---|
| **现象** | 券核销率 54.6%，但转化率只有 15%——意味着没下单的人也在用券 |
| **根因** | `coupon_used = 发券 & 核销`，漏了"必须已下单" |
| **解决** | 加 `& (y_obs == 1)`；**报告改为双口径**：占已发券 8.28% / 占已下单 54.82% |
| **启示** | 一个指标如果有两种合理分母，就**必须同时报两个**。只报一个必然引发误读 |

### 2.4 SQL 视图用 `MAX` 取券成本（**由审稿人发现**）

| 项 | 内容 |
|---|---|
| **现象** | `v_user_profit.coupon_cost` 对多单用户取最大单券成本而非求和 |
| **根因** | 写 SQL 时按"每用户一单"的心智模型写 `MAX`，正好违反 R3（券成本只扣一次 = 每单各扣一次再求和） |
| **为什么测不出** | v1 的 DGP 每用户恰好 1 单，所以 `MAX == SUM`，9 条闸门与 20 项 SQL 单测全部通过 |
| **解决** | 改 `SUM`；并在 v2 给 DGP 加复购路径（5% 用户第二单，共 1,256 笔）来**主动构造能触发该形态的数据** |
| **启示** | **最危险的 bug 躲在"当前数据恰好不触发"的地方**。要主动构造能触发的数据形态（多单、零单、全额退款），而不是等它发生 |

## 3. 统计与实验设计类

### 3.1 我把样本量算错了，还用它去校准子代理

| 项 | 内容 |
|---|---|
| **现象** | 给子代理的手算基准写成 `31789`，正确值是 **31788** |
| **根因** | 手算 `7.8489 × 4050` 时的算术失误 |
| **发现** | 派活后自己复核了一遍，发现不一致，立即发消息更正并**明确禁止它为了凑 31789 去改公式** |
| **启示** | ① 给下游的"标准答案"一定要**用代码复核**再过手；② 发现给错了必须立刻更正，否则下游会为了迁就错误答案而破坏正确实现 |

### 3.2 一个假设的取值改变了结论（`profit_sd` 45 vs 10.8）

| 项 | 内容 |
|---|---|
| **现象** | 我假设利润指标标准差 σ=45 元，据此算利润支样本量 31,788，结论是"利润是约束者" |
| **真相** | 实测 σ = **11.08 元**（v2；87% 用户利润为 0），利润支只需 7,709 人，**转化率才是约束者** |
| **影响** | 结论直接翻转；且我按错误假设给子代理写了断言 `binding_metric == "profit"`，它会去"修"正确的代码 |
| **解决** | 改配置为实测值；同时改掉子代理的测试断言，并把"取较大值"的逻辑本身做成测试（σ 翻倍则约束者翻转） |
| **启示** | ① **外部假设必须标注来源**，并在报告里说明"若真实值是 k 倍，样本量乘 k²"；② 不要断言"哪个指标是约束者"，要断言"取较大值这件事成立" |

### 3.3 稳健性扫描里 4 个扰动有 2 个完全没生效

| 项 | 内容 |
|---|---|
| **现象** | 扰动「基线转化率」「券面额响应尺度」时，结果与基准**一模一样**（三个倍数同值） |
| **根因** | ① DGP 读的是 `dgp.l1.p0.target_mean`，而 `business.baseline_conversion` 只用于样本量公式——**改错了旋钮**；② 面额效应是 `g(f)/g(f_ref)`，在 f = f_ref 处恒等于 1——**这个旋钮在设计上就是空的** |
| **发现** | 12 个单元里有 6 个数字完全相同，机械地看出来了 |
| **解决** | 基线转化率改打 `dgp.l1.p0.target_mean`；面额改为显式传 `face_value` 给 `dgp.build` |
| **启示** | **扰动实验必须先证明"扰动真的生效"**。加一条断言：扰动后基准指标必须变化，否则扫描是空转。否则你会得到"结论非常稳健"的假象——其实什么都没测 |

### 3.4 一个"上界"其实不是上界（**由审稿人发现**）

| 项 | 内容 |
|---|---|
| **现象** | 论文写"真值最优（上界）0.405，定向达上界 86.1%" |
| **真相** | 那个 0.405 是 `贪心(真值τ) + 局部改进` 的**启发式解**，真最优 ≥ 0.405，故真实比值 **≤ 86.1%**（LP 松弛上界 0.404745 只比它高 1.8×10⁻⁷，所以差距极小——但"上界"这个称谓仍然是错的） |
| **启示** | **"上界"是一个数学承诺，不是一个好听的名字。** 只有松弛解（LP relaxation）或穷举才能叫上界；近似最优解只能叫"近似最优"。方向搞反会把最好情况当成保守估计 |

### 3.5 覆盖率误差被低估一半（**由审稿人发现**）

| 项 | 内容 |
|---|---|
| **现象** | v1 的报告（λ 扫描 R=20）写"覆盖率含约 ±0.05 误差" |
| **真相** | p=0.8、R=20 时 SE = √(0.8×0.2/20) = **0.089**，是所写值的近两倍；当时"λ=0.25 覆盖率 0.75–0.85"与 0.90 的差距只有 1~1.5 个 SE，据此判"失效"并不牢靠 |
| **解决** | v2 把 λ 扫描的重复次数从 20 提到 **100**（SE ≈ 0.04），并同时给点估计与 Clopper–Pearson 区间，用区间上界而不是点估计判阈值 |
| **启示** | 重复次数 R 的精度是 √(p(1−p)/R)，**要报阈值结论前先算 SE**。R=20 只够看方向，不够判定临界点 |

### 3.6 两个"策略价值"同名不同义

| 项 | 内容 |
|---|---|
| **现象** | 一处是含基础利润的绝对口径（3.1179 起），一处是不发券=0 的增量口径；混用让 T-learner 与 Causal Forest 的差距从绝对口径的 **1.9%** 变成增量口径的 **11.3%** |
| **启示** | **同名指标必须同一口径**；若必须并存，则在表头与正文首次出现处标明，并给出换算常数 |

## 4. 工具链类

### 4.1 econml 的 `model_t` 用了回归器

| 项 | 内容 |
|---|---|
| **现象** | `CausalForestDML` 警告 `First stage model has discrete target but model is not a classifier!` |
| **根因** | 处理变量是 0/1，第一阶段应该用分类器 |
| **解决** | `model_t=_base_classifier(...)` |
| **启示** | **把警告当错误读**。这条警告指向的是"残差正交化会失准"，不是格式问题 |

### 4.2 pandoc 3.x 的若干隐式依赖

| 现象 | 根因 | 解决 |
|---|---|---|
| `\real{...}` 未定义 | 缺 `calc` 宏包 | 加载 `calc` |
| `No counter 'none'` | pandoc 对无标题表格输出 `\def\LTcaptype{none}`，`caption` 包会去 `\refstepcounter{none}` | `\newcounter{none}` |
| `\tightlist` 未定义 | 该宏由 pandoc 默认模板提供，自定义模板需自补 | 自行定义 |
| `\pandocbounded` 未定义 | pandoc 3.x 用于限制图片宽度 | 自行定义为"超宽则缩放" |
| `Shaded`/`\FunctionTok` 未定义 | 代码块触发语法高亮环境 | `--syntax-highlighting=none` |

**启示**：用 pandoc 把 Markdown 转 LaTeX 时，**要么用它默认模板，要么把它的隐式宏全部补齐**。二者之间没有中间态。

### 4.3 Windows PowerShell 5.1 按 GBK 读无 BOM 脚本

| 项 | 内容 |
|---|---|
| **现象** | `build.ps1` 报一堆"意外的标记"解析错误，中文全变乱码 |
| **根因** | PS 5.1 读取 `.ps1` 时，无 BOM 的 UTF-8 会被当作 ANSI/GBK |
| **解决** | 给脚本写 UTF-8 **BOM** |
| **启示** | 含中文的 `.ps1` 一律带 BOM。此外，"文件其实是 UTF-8，只是控制台按 GBK 显示"也会伪装成损坏——**判断编码要看字节，不要看终端** |

### 4.4 中文引号被 pandoc 转成单向 `”`

| 项 | 内容 |
|---|---|
| **现象** | PDF 里出现 `” 加购未支付”`，两端都是右引号 |
| **根因** | Markdown 源码里用了 ASCII `"`，pandoc 的 smart 扩展在 CJK 上下文里判不出方向 |
| **解决** | 在源文件里把 132 个 ASCII 双引号按配对替换为 `“”` |
| **启示** | 中文写作**从源头就用全角引号**，不要指望转换工具判断方向 |

## 5. 排版类

### 5.1 `\needspace` 正在吃掉正文（最隐蔽的一个）

| 项 | 内容 |
|---|---|
| **现象** | 我为了"表题不要孤悬页底"，在每张表前插 `\needspace{7\baselineskip}` |
| **真相** | 它注入最多约 5.2cm 的**可伸缩胶水**，让 TeX 容忍页面超高，从而**裁掉正文**——实测丢失 §9 整段与表 5 表体，且**编译零报错** |
| **发现** | 由排版子代理在逐页看图时发现"§9 不见了" |
| **解决** | 去掉 `\needspace`，改用不可分页的 `tabular` + 图只置页顶 |
| **启示** | **"编译通过"和"内容完整"是两件事。** 任何试图影响分页的宏，都必须用"字数/段落数前后对比"或逐页看图来验证没有内容被吃 |

### 5.2 图内字号在 PDF 里只剩 4–5pt

| 项 | 内容 |
|---|---|
| **现象** | 图按 `figsize≈10 in`、字号 8–10pt 出图，看起来正常 |
| **真相** | 插入时按整版心 16.3cm 放置 → 缩放 0.57–0.64 倍 → 实际字号 **4–5pt**（正文 12pt） |
| **补充** | `body.md` 里写的 `{width=0.80\linewidth}` 被 pandoc 丢弃，图实际占满版心 |
| **启示** | **必须"按最终物理尺寸出图"**：先确定图在 PDF 里的宽度（cm），再反推 figsize 与字号，而不是画大图再缩 |

### 5.3 三处表题与表体被分页隔开

| 项 | 内容 |
|---|---|
| **原因** | 去掉 `\needspace` 后，题注与表体之间的段落边界成了最优断点 |
| **状态** | 未彻底解决（列为待办） |
| **启示** | 正确做法是用 `caption` 包的原生 `\caption` 而非手写粗体题注——让浮动体自己管理题注与表体的关系 |

## 6. 元反思：为什么这些错误会发生

| 错误类型 | 次数 | 为什么危险 | 现在的防护 |
|---|---|---|---|
| **口径错**（分母/重复扣减/未按条件置位） | 4 | 数字合理，不报错 | 两条独立实现交叉校验 + 断言 + 双口径 |
| **假设错**（σ、样本量、上界） | 3 | 影响面大，会翻转结论 | 标注来源 + 敏感性 + 禁称"上界" |
| **旋钮错**（扰动没生效） | 1 | 产生"结论稳健"的假象 | 要求"扰动必须改变基准值"的断言 |
| **工具隐式依赖** | 10+ | 阻塞但会报错 | 已固化进 `main.tex` 与 `build.ps1` 注释 |
| **排版副作用** | 3 | 吃内容、缩字号，不报错 | 逐页渲染看图；按最终尺寸出图 |
| **算术错** | 1 | 会误导下游 | 代码复核 + 禁用错误答案 |
| **文档失同步**（DGP 变更未传播） | 1 | 同一项目出现两套真相，读者无法判断哪个对 | 版本说明 + 附录 D 映射表 + 一致性检查脚本（§7.1） |

**三条通用启示**：

1. **静默失败 > 显式失败**。显式失败只要几分钟；静默失败可能带进最终结论。所以要主动把"静默"变成"显式"——交叉校验、断言、双口径、逐页看图，本质都是这一件事。
2. **"我以为"和"实际"之间要加一道机器检查**。口径靠人记必错；参数靠人填必错；图靠人看必漏。
3. **给下游的标准答案必须先自证**。我自己算错的那个 31789，差点让一个正确实现被"修坏"。

### 7.1 DGP 加了复购路径后，论文更新了，8 份文档还是旧数

| 项 | 内容 |
|---|---|
| **现象** | 为落实审稿意见 B7，DGP 加了复购路径（约 5% 用户产生第二单），所有核心数字上移：真值 ATE 0.633→0.668、ITT 0.678→0.724、每元回报 1.97→2.085、定向/随机 2.56→2.86 倍、达真值贪心解 84.9%→86.1%、利润 σ 10.79→11.08、利润支 n_per_group 7,324→7,709、测试 400→404。论文（`reports/00_项目总报告.md`）已按新数改完，但 README 与 reports/01–06 共 8 份文档仍写旧数——**全项目同时存在两套真相** |
| **根因** | 数字散落在 8 份手写 Markdown 里，没有单一事实源校验。事实源明明唯一（`outputs/tables/*.csv`），却没有任何机制检查文档与它是否一致；论文是这次手动改的，其余文档靠"记得改"，而人记不住 40 多个数字 |
| **发现** | 交付前逐份文档把数字对回 CSV 时发现。**没有任何测试、断言或脚本报错**——这是典型的静默失败，和 §2 的口径错误同一类 |
| **解决** | ① 每份文档顶部统一加版本说明（数据版本 + 指向附录 D）；② 论文新增「附录 D　数据版本与数字变更记录」，给出 v1→v2 的完整映射表；③ 新增 `scripts/07_check_consistency.py`：从 CSV 读 20+ 个关键数字、扫描 README 与 `reports/*.md`，发现旧值即以非零退出码报错并打印 `文件:行号` |
| **启示** | ① **口径/DGP 变更必须同步标注版本**——"数字变了"本身不是问题，"不标注版本"才是问题；② 文档里的数字应尽量由脚本生成，至少要能被脚本校验；③ 手写文档的份数本身就是风险：每多一份手抄，就多一处会漂移的副本 |

> 一个必须解释的设计：附录 D 的映射表**故意保留旧值**（否则说不清"变了什么"）。
> 一致性脚本对那段用 `<!-- old-values-ok:start -->` / `<!-- old-values-ok:end -->` 标记豁免，
> 除此之外任何地方出现旧值都算失败。**豁免要显式、可审计，而不是"这个文件跳过"。**

## 8. 论文排版工程类（终稿阶段新增）

### 8.1 图例压在曲线上，而人眼和"看起来没问题"都靠不住

| 项 | 内容 |
|---|---|
| **现象** | 7 张论文组图里 5 张存在真实遮挡：(b) 子图的注释框**完全盖住** λ=0.50 处所有方法的点与误差棒；图例遮住曲线起点；柱内白字压住误差棒 |
| **根因** | 画图时按"把这句结论也写在图上"的思路堆注释，没有给图例与长文本留出坐标区外的位置 |
| **发现** | ① 用视觉模型（qwen3.5-omni-plus）逐张问"图例/标注是否遮挡数据"；② 写程序化 bbox 碰撞检测交叉验证 |
| **解决** | 图例一律移到坐标区外（底部或共享图例），长说明**移出图外**（多数直接删掉、写进正文），只保留必须贴在数据旁的短数值标签 |
| **启示** | 图只承担"看出趋势"，解释属于正文。凡是"图里塞一段话"的做法，最终都会遮住数据 |

### 8.2 版式检查器用"外接矩形"判遮挡，产生 245 处误报

| 项 | 内容 |
|---|---|
| **现象** | 自写的布局检查器在未改动的图上报 245 处 error |
| **根因** | 三处几何口径错误：① `ax.patch`（坐标区底色）与 `ax.spines`（边框，是 `Patch` 子类）被当成数据；② 对数轴上柱子 bbox 从 0 延伸到 −26260px，未裁剪到 `ax.bbox`；③ `Line2D.get_window_extent()` 返回**整条序列的外接矩形**——`bar(yerr=..., capsize=2)` 把 6 个误差棒帽画成同一个 Line2D，其 bbox 几乎等于整个面板 |
| **发现** | 修图代理拒绝按这个口径"消 error"，而是逐条给出反例（含 "547pt² 恰好等于该文字自身 bbox 面积"这种铁证） |
| **解决** | 改用**墨迹点云**：折线取顶点+中点、柱取路径顶点+几何中心、散点取 offsets，统一裁剪到 `ax.bbox`，再判"包围盒内落入多少墨点"（≥3 才报） |
| **启示** | 自动化检查器也会系统性说谎。**下属指出检查器错了时，先验证它的反例，而不是让它绕过检查** |

### 8.3 `\hyperref{...}{[}10{]}` 只把"["变成链接

| 项 | 内容 |
|---|---|
| **现象** | 正文文献引用仍是黑色；生成的 LaTeX 是 `\hyperref[ref:10]{[}10{]}` |
| **根因** | pandoc 把 `[10]` 转义成 `{[}10{]}`。放进 `\hyperref` 的第二个参数后，`{[}` 里的 `{` **提前闭合了参数分组**，于是链接只包含一个 `[`，`10{]}` 落在参数外 |
| **解决** | 再包一层大括号：`\hyperref[ref:10]{{[}10{]}}`，参数变成完整的 `{[}10{]}` |
| **启示** | 凡是把"被转义过的文本"塞进 LaTeX 带参数命令，都要检查分组是否还在 |

### 8.4 用编号集合而非正则去识别"表 20"

| 项 | 内容 |
|---|---|
| **现象** | 交叉引用脚本把"用户表 20 万行""事件表 120.1 万行"里的数字认成表号，生成 `tab:20` 等未定义引用，PDF 里会渲染成问号 |
| **根因** | 单遍正则 `表\s*(\d+)` 无法区分"表 20"（引用）与"用户表 20 万行"（复合词+量词） |
| **解决** | 两遍处理：先扫出题注/图环境/`\tag` 得到**合法编号集合**，正文只包裹命中集合、且编号后不跟量词的；再加负向先行断言排除 万/行/元 等量词 |
| **启示** | 在自然语言里做结构化抽取，**用"已存在的合法集合"做白名单**比调正则可靠得多 |

### 8.5 f-string 里写字面大括号

| 项 | 内容 |
|---|---|
| **现象** | `xref.py` 报 `SyntaxError: f-string: single '}' is not allowed` 与 `invalid escape sequence` |
| **根因** | 要在 f-string 里输出 LaTeX 的 `{` `}`，写了 `{{`/`}}`，但漏配一次就整行语法错；混入 `\t`/`\.` 又触发转义警告 |
| **解决** | 凡是拼接 LaTeX 片段的函数，一律改用**字符串加法**（`"\\label{tab:" + n + "}"`），不用 f-string；文件头 docstring 用 `r"""` 避免 `\.` 警告 |
| **启示** | 生成代码与生成数据是两种活：**拼接含大量特殊字符的目标语言时，拼接比格式化安全** |
