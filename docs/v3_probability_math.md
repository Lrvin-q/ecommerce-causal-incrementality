# v3 协变量、购买概率与分配机制

> 合成数据 / 已知 DGP。Phase B 实现说明；这是机制与数值校验，不是正式重复实验结果。业务参数来自已冻结的 `configs/v3/`，数值参数来自 `configs/v3_numerics.yaml`。

## 1. 接口及隔离边界

`generate_covariates(cfg, rep_id, n=None, population_kind='history', pairing_group=None)` 返回 `CovariateBatch`。其中 `users` 只含已记录的分配前特征和设计时点，`audit_u` 单独保留隐藏变量，`stream_prefix` 用于金额、退款等模块派生同一配对批次的独立潜在流。历史正整数用户 ID 与独立验证负整数 ID 不重叠；跨重复及跨场景的实体键仍须加 `run_id`。

`purchase_probabilities(users, cfg, audit_u, integrate_u=True)` 返回两套概率：`p0_conditional/p1_conditional` 条件于完整 X 与实现的 U，`p0_given_x/p1_given_x` 对 U 积分。前一套用于抽取潜在购买，后一套与金额核的购买者条件期望相乘，构成 X-only 真值。两套都属于模拟/审计侧，不能进入学习接口。引擎抽样、AA 和独立 MC 可显式设置 `integrate_u=False`，此时两个 X-only 字段为 `None`；需要审计时再明确求积，避免在每批生成时付出尚不需要的积分开销。

`assign_treatment(...)` 只生成历史日志分配。返回 `action`、分析 `label`、可观测 `design_probability`，另列 `true_propensity` 与校准截距供审计。观察性 L3 的 `design_probability` 为缺省值，不能用总体目标比例代替个体倾向。独立验证必须由后续政策臂随机化实现；将 `population_kind='validation'` 传给历史分配函数会抛错。

## 2. 记录精度与公共随机数

每种协变量使用自己的 `child_rng(master_seed, stream, rep_id)`：新客、两种历史交易额、购物车、浏览深度、渠道、日历队列、周内日期和 U 均分开。历史交易额与购物车先按配置的分币单位记录，机制的标准化、购买及分配分数全部从这些记录值计算，不读取另一个未记录的舍入前版本。新老客的 Gamma 抽样各自生成完整长度后选取，构成变化不会让后续用户的随机数位移。

同一配对族扩展样本量时，已有用户的全部特征、U 和后续潜在流保持前缀一致。L2 时序对照经 `cross_pairing_references` 连接到人数/分流基准；L3 重叠与 U 形状对照连接到固定真值扫描，因此跨名称的对照也使用相同基础随机数。真正 AA 与设计功效保留各自独立配对族。

U 分布统一由同一均匀随机数 q 的逆分布产生：

\[
U_N=\Phi^{-1}(q),\qquad
U_L=\frac{\sqrt3}{\pi}\log\frac{q}{1-q},\qquad
U_B=\sqrt3(2q-1).
\]

三者理论均值为零、方差为一；支持和尾部不同。随机生成器若恰好生成零，只将该浮点端点替换为相邻的内部可表示数，以避免逆分布无穷大。没有对生成的 U 做尾部裁剪。

## 3. 固定参考校准与正余量

机制标准化使用独立、固定命名流的参考人群，人数来自 `design.numerical.calibration_reference_n`。它不属于任何训练、验证、测试或正式重复。参考标准差使用总体分母；不对标准化后的真实机制特征做 ±3 截断，分析侧预处理由 Phase C 独立实现。

记 z(X) 为已记录 X 的机制特征，b(X) 为基线线性分数，g(X) 为效应分数。效应分数消费配置的异质性倍数和新客×购物车交互。参考人群上先解两个截距：

\[
E_{ref}[\sigma(\beta_0+b(X))]=p_{target},\qquad
E_{ref}[\sigma(\gamma_0+g(X))]=h_{target}.
\]

再令

\[
h(X)=\sigma(\gamma_0+g(X)),\quad
a=\frac{\Delta_{target}}
{E_{ref}[(1-p_0(X))h(X)]},\quad
p_1(X)=p_0(X)+(1-p_0(X))a h(X).
\]

三个配置分别约束基线平均概率、异质性形状平均值及购买增量平均值，不能把它们混为同一截距条件。必须检查 `0≤a≤maximum_purchase_increment≤1`；不可达时抛错，不能裁剪 p1 后声称平均增量达到目标。`maximum_purchase_increment` 在此保守地限制余量系数 a，因此也界定 L1 的个体概率增量上限。

当异质性系数倍数为零时，h 可为常数，但由于剩余概率空间仍随 p0 改变，最终增量不必完全常数。该格的含义是取消配置的效应分数异质性，并不等价于 L0-P。

L0-P 和 L0-Π 单独读取常数 p0 与购买增量，完全不套用上述异质机制。L0-Π 的可行域、成本控制和毛利旋钮由控制模块处理。购买零增量但存在发券成本仍可能有非零利润效应。

## 4. L2 日历与迁移

历史 L2 按冻结的队列份额分块：从份额的有理数分母推导最小块长度，每块对队列标签独立随机排列。冻结正式人数是块长的整数倍，因此每个正式 n 的各活跃队列人数准确满足设计，同时任意 n 的前缀保持不变。队列先决定训练/验证/测试期，再按该期的构成设置新客概率和渠道概率。周内日期来自独立流，真实分配日为 `(week−1)×days_per_week+within_week_day`。

冻结漂移序列 d(t) 作用于余量系数：

\[
p_{1,t}(X)=p_0(X)+(1-p_0(X))a h(X)d(t).
\]

L1 的上限约束是漂移前的基准约束；L2 有意允许不同周的增量更高或更低，但必须逐用户检查 `0≤a h(X)d(t)≤1`，不做概率裁剪。构成变化改变 X 分布，不重估参考标准化或机制截距。

独立验证从历史测试期的队列按其归一化份额抽样，并使用测试期构成；不会重新混入早期训练人群。非 L2 历史 `split` 标为 `pending_stratified`，由 Phase C 在真实处理分配后按冻结的 T/渠道/新老客分层拆分。本模块没有以独立随机拆分偷偷替代该约束。

## 5. L3 两个旋钮与 X-only 积分

L3 固定复用上述 L1 参考校准系数，再加入结果旋钮：

\[
p_0(X,U)=\sigma(\beta_0+b(X)+\lambda_Y U),\qquad
p_1(X,U)=p_0(X,U)+(1-p_0(X,U))a h(X).
\]

不在每个 λY 重新校准基线与平均增量；否则会抵消预设的联合机制变化。λT 不进入任何潜在购买、金额或结果参数。固定 λY 扫描 λT 时，同一配对重复的潜在概率及积分真值逐元素不变。

分配单独使用

\[
e(X,U)=\sigma(\alpha_0+s\alpha^Tz(X)+\lambda_T U).
\]

每个重复只解分配截距 α0，使当前有限人群平均 e 等于指定处理比例。实际处理人数仍是 Bernoulli 实现，不强制恰好等于目标人数。α0 的校准使用机制侧 X、U，不是让分析侧得到真实倾向或隐藏变量。

因为 U 与 X 独立、金额核又与 U 独立，X-only 真值先求

\[
\bar p_0(X)=\int p_0(X,u)f_U(u)du,\qquad
\bar p_1(X)=\bar p_0(X)+(1-\bar p_0(X))a h(X).
\]

于是 `τΠ(X)=p̄1(X)A1(X)−p̄0(X)A0(X)`，而不能用当前用户实现的 U 或个体潜在利润差替代。

默认 `integration_method='batched'` 在各分布有限分位点间做 Gauss–Legendre 数值求积，截去的概率质量不超过数值配置的预算；被积概率有界于 [0,1]，该质量直接给出尾部绝对误差界。节点逐次加倍，在每个输入 X 比较相邻规则，同时加上权重总质量误差与尾部界。达到配置精度才返回，否则抛错。`integration_error_per_row` 保存每个用户自己的相邻规则差、质量误差与尾部界之和，`integration_max_abs_error` 仅用于概览，不能把该最大值广播给全部用户后做利润相对误差判断。这是数值收敛诊断与已知尾部界之和，不是对求积误差的数学全局证明。

`integration_method='adaptive'` 供引擎对利润误差检查未通过的近零效应行进行精细重算。它消费数值配置的 `refinement_epsabs/refinement_epsrel/refinement_limit`，以 `scipy.integrate.quad` 对每行完整支持积分，不截掉分布尾部。利用三种 U 的对称性，负分数在正半轴对 `σ(s+λu)+σ(s−λu)` 积分，正分数取负分数结果的补数；s=0 时概率严格为 1/2。误差记录为 quad 的逐点绝对误差估计，加结果/补数运算的一单位浮点间距。λY=0 时直接使用 sigmoid，积分误差为零。自适应法没有统一固定节点阶数，`integration_nodes=0`；该字段不能解释成没有执行求积。

低层 `integrate_baseline_over_u(..., return_per_row=True)` 返回 `(values, max_error, nodes, error_per_row)`，默认仍保留前三项接口。`purchase_probabilities` 返回逐行数组，跳过积分时为 `None`，已经解析确定且不需要 U 积分的层为全零数组。测试用不同积分区间的独立自适应求积交叉核对三种 U，并检查对称恒等式、逐行误差和机制条件概率不变。

利润尺度传播必须利用 p1 与 p0 共享的同一积分误差，而非假设两个误差独立。令 k=ah，则 `p̄1=k+(1−k)p̄0`，概率积分误差的利润放大系数为 `|(1−k)A1−A0|`。引擎还须合并金额核误差、交叉项与数值运算误差，逐行检查绝对和相对门槛同时成立；概率求积通过不代替利润尺度验收。对近零效应先精细重算，不能将两项门槛换成满足其一即可。

## 6. 真正 AA、功效接口与验证范围

AA 的所有用户实际动作由 `design.aa.actual_action` 决定；虚拟标签来自独立命名流。标签不进入协变量、购买概率或金额核，因此两标签之间没有真实处理效应。潜在发券状态仍可定义，但不会被当作 AA 的实际处理。购买增量为零的发券实验与这个 AA 是不同实验。

设计功效的活跃 MDE 倍数只登记目标，Phase D 必须通过合法购买增量反解并检查实际达到的利润效应；本模块不直接把 MDE 倍数乘在已实现利润上。不可把尚未实现的功效设计格称作完成。

主引擎的生成与审计入口现已调用 `dgp/v3_semantics.py` 中的 `validate_mechanism_semantics`，核对已实现的分布、账务、共享随机性、U 标准化和校准语义。改变一个语义标签而没有对应实现时会拒绝执行；连续业务参数仍在各自合法域内消费。该入口校验已实现，不再列作后续口头约束。

测试文件 `tests/test_v3_probabilities.py` 检查全部完整场景可执行、配置未被 n 较小的机制测试改写、固定参考校准、L2 正式人数与任意前缀、未来验证人群、固定真值扫描、联合扫描、跨族公共随机数、独立 U 积分、实际时间漂移、AA 与不可达目标拒绝。测试不代替正式 R，也不验证 Phase C 的分层拆分、SQL、污染清洗或后续估计覆盖率。

## 7. 计算与缓存

缓存键包含种子、参考人数、参考协变量分布与记账分币单位；效应校准另外包含完整 L1 概率参数。缓存不依赖 λT、重复号或最终样本 X。参考矩阵为只读数组，校准只缓存标量及特征矩；U 积分按配置批量求值，不创建完整人数×最大节点数的大矩阵。`clear_probability_caches()` 可显式释放引用。

冷缓存的参考矩阵为 `reference_n×7` 个浮点数；机制输入输出数组、生成参考人群的暂态表和校准中间数组也需计入内存。进程间不隐式共享缓存。工作进程数必须由全链实测内存决定，不能只按最终矩阵大小估算。

本阶段已对正式人数规模执行过冷缓存机制计时并测量 Python/NumPy 追踪分配峰值，主控负责将原始数值落到结果表。开启追踪会增加耗时，追踪峰值也不是操作系统进程 RSS；不能把该单次机制计时冒充 Phase D 的多次、三种工作负载成本 pilot。
