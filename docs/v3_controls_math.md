# L0-Π 人工控制的计算与可行性

> 合成数据 / 已知 DGP。这里的商品成本率与核销概率调节仅服务控制实验，统一称为“同质化旋钮（control knob，非业务机制）”。本文件是 Phase B 实现说明，不能代替独立评审或正式重复实验。

## 输入与输出边界

`solve_l0_profit_control(cart_cent, p0, p1, cfg)` 接受已按分币存储的真实购物车金额、两种处理状态购买概率与场景配置。只有显式启用控制、层级为 L0、profile 为 `l0_profit_control` 的配置才可调用；L0-P 与 L1–L3 会抛异常。结果的 `goods_cost_ratio` 和 `redemption_probability` 只用于微观交易生成；`audit` 是独立审计表，不得成为学习特征、策略资格或选模依据。

同一用户的有效商品成本率同时作用两种处理状态以及首单与复购单。实际交易按金额模块逐组件记账；本模块没有向利润加常数，也没有修改已算出的 CATE。未达到目标的用户保留自然商品成本率和自然核销概率，不删除样本。

## 先诊断购买概率

固定自然成本率和自然核销概率。记 `A0`、`A1` 为条件首单发生时，两种处理状态对应的 30 天期望净贡献；它们包含首单金额、首单核销、退款、复购和各事件截窗。

固定 `p0` 而允许 `p1` 在闭区间 `[0,1]` 内变化时，利润效应是 `p1 A1 − p0 A0`。合法可达区间为 `−p0 A0` 与 `A1 − p0 A0` 两端点排序后的区间。若 `A1` 非零，达到目标 `τ*` 所需的概率为 `(τ* + p0 A0) / A1`，审计保留其原始数值，即使它为负或超过 1。若 `A1=0`，效应不随 `p1` 变化，另按目标残差判断并将无唯一解的概率记为 NA。

此诊断允许“减少亏损订单”产生正利润效应。它不等于固定购买概率的人工成本控制可行，也不表示应该在业务上压低购买率。

## 真实等期望成本

记 `D=min(face,G1)` 为首单核销时的实际抵扣，`s1` 为首单在 30 天窗口内的概率，`r1_time` 为首单退款在窗口内的概率，`q1` 为发券状态每单退款概率，`I_return` 表示退款是否退券。条件核销概率为 1 时，每名被发券用户的期望实际核销支出为

`M = p1 E[D] (s1 − I_return q1 r1_time)`。

因此，等成本核销概率是 `c* / M`。冻结场景不退券且首单都在 30 天内，公式简化为协议的 `c* / {p1 E[D]}`；实现仍用完整时间与退券语义求分母。`M=0<c*` 或算得概率不在 `[0,1]` 时标记不可行，绝不把概率裁到 1。异质成本场景始终使用自然核销概率。

等成本仅在“利润控制与成本控制共同可行”用户上实际施加。若成本概率合法而利润目标不可达，两项参数都回到自然机制，审计分别记录成本可行、利润不可行以及最终未施加控制。这能避免部分成功被误报为整套控制成功。

## 分币目标与数值搜索

每个购物车金额的首单分币分布来自截断正态 CDF 在整数分区间上的精确概率差。金额模块对各个支持点分别计算首单、复购、商品成本、商品回收、手续费及券封顶，随后按概率求和。时间系数来自独立确定性积分。本模块直接调用这个同源期望接口，没有用已实现订单金额替代条件真值。

为提出初始候选，暂时只去掉商品成本与回收成本的分币舍入；订单总额、手续费与券封顶仍保留其真实分币期望。令 `d=p1−p0`、`b=p1 q1−p0 q0`、`h` 为可回收比例、`ρ` 为条件复购概率，关于成本率 `g` 的系数为

`B = E[G1](−d s1 + b h r1_time) + ρ E[G2](−d s2 + b h r2_time)`。

从自然成本率下的完整期望中扣除已经舍入的商品成本与回收贡献，得到其余部分 `A`，再以 `(τ*−A)/B` 提出候选。这个解析候选只有通过完整分币期望的残差检查后才会被接受。

搜索域由配置毛利率边界转换成商品成本率边界。域转换使用十进制有理数运算，避免把数学上的 0.02 写成 0.020000000000000018 而误触半分边界。所有候选最终仍按金额模块的十进制 half-up 规则记账。

真实目标函数是阶梯函数。实现先检查两端点与解析候选；尚未命中容差才按配置做有界二分，检查已评估候选的最近残差。配置固定最多 200 次、参数区间容差 `1e−10`、利润误差容限 0.001 元/人。达到参数精度并不等于达到了利润精度；没有合法值通过利润残差检查时，结果仍为不可行。

单调性来自两种状态共用商品成本率：成本增量为 `ΔK≥0` 时，half-up 回收成本增量满足 `0≤ΔR≤ΔK`。冻结的 `p0=.1`、`p1=.15` 和退款参数使净商品成本项随 `g` 单调下降，事件截窗只会减小回收权重。代码检查这一充分条件；对无法证明单调方向的其他购买概率组合抛错，不擅用二分法。

## 全体与共同子集

审计逐用户保存购买概率可行区间和所需 `p1`、成本可行性、利润可行性、实际施加控制与否、自然和控制后的利润 CATE、核销成本、解析候选和最终残差，以及未通过的原因。低金额、零金额、不可行用户均留在原批次。

`audit_common_feasible_mask(equal_cost, natural_cost)` 仅供观测策略和评估冻结后的审计调用。它检查两批购物车和概率的顺序一致，再取两个控制可行域的交集；不改动两批原始结果。主控仍须按用户 ID 配对，并同时报告全体、各自可行子集和共同子集的特征与结果。共同子集不能作为生成时的资格条件。这里的“同质”始终指预先约定的数值容限内同质；排名、相关系数、R² 的审计处理按协议执行。

## 计算与验证

求解按 `(完整 SHA-256 配置哈希, cart_cent, p0, p1)` 缓存标量结果；同一批次先对这些键去重，再还原原始用户顺序。容量来自 `configs/v3_numerics.yaml`，金额模块另缓存少量 PMF 和标量组件期望。缓存复用确定性积分与求解，不缓存用户随机结果，也不改变目标或精度。新的配置哈希会隔离旧解。

`tests/test_v3_controls.py` 覆盖零/低金额、合法边界、全体可行和部分可行批次、两种成本模式、退券语义、真实封顶核销支出、完整分币期望重算、自然回退、配置隔离、输入非法值与 L0 专用门禁。正式可行比例及耗时由主控机制验证脚本落盘；小样本演示仅用于核查计算路径，不能替代正式场景结果。
