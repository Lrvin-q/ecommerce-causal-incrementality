## 1. 结论

一句话理由：**核心的 size 与功效结论是可逐位复现的**——把 5 个 run-root 的 13 个 `aa_repetitions.csv` 共 1384 行按 `[level, rep]` 去重成 1000 行后，FPR 46/1000、四层 14/11/10/11、经验 SD/平均 SE 0.987–0.995、相对偏差 1.96e-15、3/6/6 分类，全部与文档一致到小数末位；但**作为 D.1 交付物的 732 行 MDE 表有 448 行不可由本行列复算**（概率指标行的 `sigma_*` 填的是利润 σ，MDE 在不等分配下系统性偏小 0.4%–4.3%），且正式文档存在 4 处口径混用 / 选择性取数与 1 处明确的数值错误（"4×MDE" 实为 4.93×）。这些不足以推翻主结论，但足以阻止"可发表/可复现"的签字。

| 层 | 复算 empirical_sd/mean_se | JSON `ratio` | 差 |

且这四组 sd / mean_se 我直接用 1000 行逐 rep 的 `full_net_profit_diff` / `full_net_profit_se` 重算，**与 JSON 完全一致**（L0 0.037895/0.038386、L3 0.046171/0.046393）。

**判定：成立，但"接近 1 说明标准误是校准的"这句结论的强度被高估。**

1. **没有把覆盖率当第二份证据——这一点做对了。** 文档 §2 主动写明"CI 含 0 ⟺ p≥α，因此覆盖率 ≡ 1−FPR，不是独立证据"（§6.3 再次重申）。这是本阶段最值得肯定的方法学自觉。
2. **但 sd/mean_se 这个比值的分辨力极低，文档没给。** 250 次下 sd 的相对标准误是 1/√(2·249)=**4.5%**，1000 次下是 **2.2%**。所以 0.987 距 1 只有 0.29 个 SE，0.9948 距 1 只有 0.23 个 SE——**这项检验只能排除 >7%（逐层）/ >4.4%（合并）的 SE 误差，对 1%–3% 的失校准无分辨力**。写"说明标准误是校准的"应改为"与校准一致，可排除约 4% 以上的 SE 低估"。
3. **合并比值被层间均值差污染了一点点。** JSON 的 `empirical_sd`(POOLED)=0.043518 是围绕总均值（−0.000121）算的，含 4 个层均值的层间方差（sd=0.003090）；纯层内 RMS = 0.043474，除以同一个 `mean_se` 得 **0.993800**，而不是 0.994819。差 0.1%，不影响结论，但"合并 0.995"这个数不是纯粹的 SE 校准量。
4. **"两条路径互证（1.020）"无法验证。** 我在 `docs/` 全目录检索 `1.020`，只有这一句自述，没有对应的产物、脚本或评审记录（`docs/reviews/*` 中无此数；日志里的 1.02 是 DR/ITT 的 SE 比值，另一回事）。而且 1.020 与 0.995 相差 2.5%，正好落在合并口径 2.2% 的分辨力之外沿——**这两个数不足以"互证"**，只能算"同量级"。建议删除该句或补出处。

### S3 — 虚拟标签 AA 的有效性（Y(1)≡Y(0)、actual_action=0）

**判定：论证成立，但覆盖范围被表述得比实际宽，需收窄措辞。**

- **真值为 0 的推导是对的，不是假设。** 标签走独立随机流 ⇒ 给定 X 两臂结果同分布 ⇒ E[Π|B]−E[Π|A]=0。我在数据层验证了三条不变量：1000 个 rep 的 `actual_action_share` **全为 0**、`coupon_cost_total` **全为 0**、`n_total == registered_n == 200000`；`label_share` 落在 [0.497035, 0.503840]，理论 SE=0.001118，最大偏离 3.4 SE，无系统偏斜。SRM p<0.001 出现 **1/1000**（名义值 1/1000）。
- **券成本确实被固定住了**（恒 0，已验证），所以 §3 那句"券成本恒为 0"是准确的。
- **但"退款同率"和"成熟窗口"只是"两标签之间相同"，不是"与真实发券臂相同"。** `actual_action=0` 意味着券永远不发、核销永不发生，因此：券致退款路径、券驱动订单的成熟截断、金额拆分在 treatment 侧**一次都没执行过**。文档 §6.2 把这层局限窄化成"不覆盖发券臂的券成本方差"，实际未覆盖的是**整个 treatment-arm 执行链路**。B/C 的记账校验是账面恒等式校验，不是 size 校验，二者不能互相顶替。
- 因此 §3 的小标题"为什么这个 AA 是有效的"应改为"这个 AA 有效覆盖了什么、没覆盖什么"。**这不影响 FPR 结论的正确性，但影响读者对"AA 通过 ⇒ 整条链路无偏"的推断边界。**

| 项 | 文档值 | 复算值 | 判定 |
|---|---|---|---|
| 购买率拒绝 | 8/100 = 0.080 | **8/100 = 0.0800** | 一致 |
| 购买率 CP95 | [0.0352, 0.1516] | **[0.035172, 0.151558]** | 一致 |
| 二项 P(X≥8│100, .05) | 0.128 | **0.12796** | 一致 |
| 利润拒绝 | 100/100 = 1.000 | **100/100** | 一致 |
| 利润真值 | 约 −0.56 | **−0.55898**（`effect_at_zero_increment`，L0） | 一致 |
| 真值/设计 MDE | **≈4×** | **4.93×**（0.55898/0.113341） | **错误** |

**判定：披露是诚实的（判定"成立"），但 4×MDE 这个数错了。**

1. **"1.6 倍"没有被含糊过去，这一点做得好。** §4 原文"点估计 0.080 是名义值的 1.6 倍，**必须点名披露**……R=100 的半宽约 ±0.06，既判不出真实膨胀、也排除不了——这一列只能描述，不能判定"。这是本文件里质量最高的一段：既给了点估计、又给了区间、还明说了这一段没有判定力。**不需要改。**
2. **1.000 被正确解释为功效，没有读成"AA 失败"。** 而且文档用 `block` 列把负对照与 AA 机械隔开（JSON `rows_excluded_non_true_aa=0`，`17_merge_aa_layers.py` 只汇总 `block=true_aa`），我在合并 CSV 里确认 15 行全是 `block=true_aa`，负对照没有混进来。**判定：成立。**
3. **但"≈4 倍设计 MDE"是错的，应为 4.93×。** 0.55898/0.113341=4.93。若要得到 3.86× 需用 `n=100000/单侧/90%` 那行（MDE=0.144998）——这说明该数字很可能取错了行。它出现两次（§4 表格"真值约 −0.56 元/人 ≈ 4×MDE"、§4 正文"≈4 倍设计 MDE"）。方向上偏保守（真实功效比 4× 时更高），但仍属数字对不上。
4. **文档漏掉了一个对自己有利的证据**：AA 在 L0 的购买率是 7/250，负对照是 8/100，同一场景同一条链路可合并为 **15/350 = 0.0429，CP [0.0242, 0.0697]，二项 p=0.624** ——比单独 0.080 有力得多，也直接消解"0.080 是否意味着膨胀"的疑问。建议补上（负对照的 KS 均匀性检验也做了：KS=0.1006, p=0.2467，同样支持"无 size 失效"，文档也未引用）。

### S5 — 15 个功效格的两个 achieved

| 项 | 文档值 | 复算值 | 判定 |
|---|---|---|---|
| `relative_deviation` 最大 | 1.96e-15 | **1.959091e-15**（L0 的 mde050 与 mde100） | 一致 |
| `achieved_effect` 绝对差最大 | 0.0059（L1 mde200） | **0.005917**（L1 mde200） | 一致 |
| 该格相对差 | 2.3% | **2.27%** | 一致 |
| 全体最大相对差 | （未给，隐含即 2.3%） | **7.84%**（L1 mde050） | **选择性取数** |

**判定：前半成立，后半的归因错误。**

- **解析端 1.96e-15 完全成立**，且我把 15 行的 `relative_deviation` 全部重算，最差就是 1.96e-15（出现在 L0 的 mde050 与 mde100；L1 mde200 恰为 0.0）。"目标 → 概率增量 → 重积分"的反解没算错，这个结论可以签字。
- **"最大绝对差 0.0059、相对 2.3%"是挑了最有利的一格。** 绝对差最大确实在 L1 mde200，但那一格的相对差恰好最小（2.27%）；**最大相对差是 7.84%，在 L1 mde050**（−0.005107/0.065131）。用"绝对差最大的那一格的相对差"来代表"相对偏差的量级"，会让读者以为最坏情况是 2%。改法：两个口径都报，或统一用 `diff/design_mde`（最大 4.54%）。
- **"这是 100 次抽样的 MC 误差，不是构造偏差"——归因不成立。** 关键证据是层内离散度：

| 层 | 5 格 diff 均值 | 格间 sd | 单格 MC SE | z（按 1 自由度） |
|---|---|---|---|---|
| L0 | −0.001061 | 0.000651 | 0.003665 | −0.29 |
| L1 | **−0.005466** | **0.000332** | 0.004775 | **−1.15** |
| L2 | **+0.004057** | **0.000750** | 0.004239 | **+0.96** |

  L1 的 5 个格（目标从 0.065 到 0.261，跨 4 倍）差值全部落在 [−0.0059, −0.0051]，**格间 sd 只有 0.00033，是单格 MC SE 的 7%**。如果这是 5 次独立抽样的 MC 误差，格间 sd 应该 ≈ MC SE（0.0048）；实际小一个数量级，说明**这 5 格共享同一个随机实现（common random numbers），真正独立的只有 1 个自由度，而不是 5 个**。按 1 个自由度算，L1 是 −1.15 SE、L2 +0.96 SE，都判不了显著——所以"不是构造偏差"这个**结论方向上是对的，但论证方式是错的**（不能拿 15 个格当 15 份独立证据，也不能用"MC 误差"这个词描述一个层水平的共同偏移）。正确写法：**"层内 5 格几乎无离散，差异是一个层水平的共同偏移；按 1 个自由度计 z=−1.15，尚不能判为偏差，但也不能排除约 −0.4% 量级的系统性偏移（2 SE 上限约 0.0095 元/人 = 0.08×MDE）。"**
- 实践影响：最大差 0.0059 ≈ 0.05×设计 MDE，对功效曲线的判读无影响。所以这不是"结果错了"，是"证据被高估了"。

### S6 — 边界格分类（6 below / 3 boundary / 6 above）

**判定：分类与读数成立；"零余量"的论证依据在表里不可复算，且只对设计期成立。**

- 分布确认：`below_design_mde` 6 / `boundary_zero_margin` 3 / `above_design_mde` 6，合计 15。三个 boundary 恰好是 L0/L1/L2 的 `mde100`。
- **"设计功效正好 0.80、零余量"是构造性的，不是实证发现。** 我复算了三层的 `design_mde/(2.801585×SE_design)` = 0.999995 / 0.999998 / 1.000002 —— MDE 的定义就是 (z₀.₉₇₅+z₀.₈)×SE，所以 1×MDE 格的设计功效**恒等于 0.80**。文档 §7.4 把它写成"σ 只要低估 1 个 SE 就掉到 0.79 以下"，读起来像经验判断，实际是定义使然。建议明说"1×MDE 格的 0.80 是定义值，因此该格不能作为'可检出'的证据（否则是循环论证）"——这个理由比"零余量"更硬。
- **"1 个 SE"有表内依据，但不可复算。** MDE 表 power_cell 行的 `power_at_sigma_plus_1se` = **0.7912 / 0.7904 / 0.7913**，确实"掉到 0.79"，与文档一致。但支撑它的 `sigma_relative_se_treatment/control` 两列在 20 个 power_cell 行里**全为空**，所以"1 SE"到底取多少无从核对。我反推：要把 0.80 打到 0.79，σ 需被低估 **1.26%**；而 n=200k 下 σ 的相对标准误只有 0.158%（对应功效 0.7987，仍在 0.79 以上）。**说明这里的"1 SE"用的是先导样本（n≈4k–10k，notes 里 `sqrt((kurtosis-1)/(4*n_train_arm))`）的 σ 估计误差，不是注册 n 的。** 这在设计期是合理的，必须写明，否则读者会以为注册规模下也有这个脆弱性。
- **实测 0.87/0.78/0.85 与"名义 0.80"自洽。** 三格 CP 全部含 0.80（[0.7880,0.9289]、[0.6861,0.8567]、[0.7647,0.9135]）；合并 250/300=0.8333，单侧二项 vs 0.80 **p=0.083**；单格 p=0.056/0.686/0.139，无一显著。**"围绕 0.80"这个读法成立。**
- **但"零余量"只对设计期成立**：实测 σ_t 为 8.938/10.202/10.202，比设计 σ（9.283/10.471/10.469）低 **2.6%–3.7%**，所以用实测 σ 算的名义功效是 **0.8242/0.8188/0.8079**，不是 0.80。L0 有 +2.4pp、L2 有 +0.8pp 的余量，L1 才真的贴边。文档只引 0.80 这个数，读者会误以为三格都不留余量。**建议同时报两列（表里本来就有），并说明"设计期零余量、实测期有余量"。**
- 一个字面冲突：MDE 表里这三行 `detectable_at_80 = True`、`boundary_flag = True` 并存，而正式文档说"不得计入可检出"。字段级没有问题（前者是"达到 80% 阈值"的谓词），但用在验收文档里会互相打架，需加一句说明。

### S7 — L3 的 5 格为何不跑

**判定：排除的统计理由成立（我独立验证了推导），但"F 阶段能修"是未验证的假设，且证据不在任何正式产物里——这一条最接近"掩盖问题"。**

- **推导正确。** e(x) 随 X 变化时
  E[Y|T=1]=Σe·μ₁/Σe、E[Y|T=0]=Σ(1−e)·μ₀/Σ(1−e)，与 μ 同向相关时两臂简单均值差 ≠ ATE，且偏差是**估计目标层面的**，不随 n 缩小。文档 §7.5 的说法（"目标是倾向加权对照而非 ATE"）在因果推断上是正确的，不能算"找借口"。
- **量级对得上。** L3 设计 MDE（1×、n=200k、50/50、双侧 80%）= 0.130823；selection bias 1.4351/0.130823=**10.97×**，1.4267→10.91×，与文档"≈11 倍"一致。0× 格 10/10 拒绝也与"偏差 ≈11×MDE"一致。
- **但有三个可追责的缺口：**
  1. **1.43 这个数不出现在任何正式产物里。** 15 格正式 CSV 的 `selection_bias` 全为 1e-16（L0–L2 的机器零，`propensity_min=max=0.5`，这一列本身是好的），L3 一行都没有；`v3_phase_D_mde.csv` 里**根本没有** `selection_bias` / `selection_bias_ratio_to_mde` / `propensity_*` / `estimator_warning` 这几列。所以 +1.43 只能追到 `docs/v3_phase_D_local_power.md` §5 的**n=3000、R=10 的小规模表**（`L3_power_mde200`，`realized_effect_reps=10`）。正式文档 §7.5 把它当成 7 节的正式结论引用，**没有标注它是 pilot 数**。一个用来整体排除 5 个格的裁决，只靠 R=10 的 pilot 支撑，且不落盘，这是可复现性缺陷。

  3. **两处文档对 L3 的识别模式给出不同答案。** `v3_phase_D_local_power.md` §5.1 说"L3 的随机化概率依赖 X"（=随机化设计，e 已知），`v3_phase_D_models.md` 说"L3 是观察性层，没有已知设计概率"（=observational）。这两个说法决定了 F 阶段能不能用设计概率，必须统一。
- 结论：**排除 5 格这个决定本身可以放行**（不跑是对的，跑了是 19 CPU·h 的假曲线）；但文档必须把这 5 格在注册表里显式登记为 `not_evaluated_reason=estimand_mismatch`，并把"F 能修"降级为"待 F 验证"。**D 阶段的实际覆盖率是 15/20，不是 20/20**，这一点必须在验收口径里写死。
