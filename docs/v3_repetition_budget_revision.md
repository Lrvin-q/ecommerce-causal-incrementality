## 1. 为什么可以砍：成本结构说明

单批 20 万人的实测成本（`docs/v3_phase_D_pilot.md`）：

| 作业 | 内容 | CPU 秒 |
|---|---|---|
| `historical_dgp_jobs` | 只调用 `generate_v3_population`，内存里生成，不落盘、不建库、不拟合 | **0.85** |
| 完整学习批 | 生成 + 五表落盘 + 污染/清洗 + SQLite + 17 条 SQL + 52 列观测表 + 4 模型 | **266.7** |
| 独立验证批 | 同上但不拟合 | 144.6 |
| 完整 AA | 同上 + ITT | 145.6 |

266.7 秒的构成：**数据工程 144 s（54%）+ Causal Forest 117 s（44%）+ T/S 4.5 s + DGP 0.85 s（0.3%）**。

**结论：DGP 不是瓶颈；钱花在"搬数据进库"和"300 棵树 × cv=3 的因果森林"上。**
因此缩减应从**批数**和**单批成本**两侧同时下手，而不是牺牲样本量 N 或模型规格。

## 2. 缩减原则

1. **保住广度**：73 个场景每格至少跑 1 次完整链路，证明"这一格存在、方向明确"。
2. **集中重复**：高 R 只给会进摘要与结论的核心格；外围格的结论只写方向与量级。
3. **精度可报告**：每一格都标注自己的 R 与该 R 下的蒙特卡洛标准误，不许把 R=30 的结果写成 R=200 的强度。
4. **不削 N 与模型**：20 万人、CF 300 棵、`cv=3`、`min_samples_leaf=60` 全部不动——它们决定结论是否可信。
5. **AA 与验证不取消**：它们是"随机化有效"与"策略真能复制"的唯一证据，只降 R。

## 5. 必须同时接受的代价（写进论文局限）

1. **外围格的精度下降**：R=30 时覆盖率 SE≈0.040，只能判"显著低于 0.90"这类大偏差，判不了 0.88 与 0.90 的差别。
2. **Tier2 多数格只有单次观测**：不能报告区间，只能报告点估计与"方向"；正文引用时必须写明"N=1，无区间"。
3. **再训练 bootstrap 只有 20 次**：足够看出"再训练确实增加方差"，不足以给出精确的分位数。
4. **AA 的 FPR 有 MC 误差**：R=800 时 SE≈0.008（合并四层），不能声称"精确等于 0.05"。
